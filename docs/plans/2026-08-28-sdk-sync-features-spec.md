## 3. Звужена постановка

Первісна ідея «агент перемикає `done: false → true`, якщо код уже є» **відкинута**: це судження без джерела істини, його неможливо перевірити програмно, а R5 вимагає перевірки.

Агент працює з **посиланнями на id у комітлозі**:

1. Коміт каже, що `ARCH-5` полагоджено, а в реєстрі `done: false` → розбіжність.
2. Коміт описує роботу, якої в реєстрі немає → пропуск.

## 5. Знахідка, що змінила дизайн guardrail R3b

Демо уроку і слайд лекції стверджують, що `--allowed-tools` є «security boundary на рівні файлової системи». Це **не так**.

README пакета `claude-agent-sdk` версії 0.2.147, розділ «Using Tools», дослівно:

> `allowed_tools` is a permission allowlist: listed tools are auto-approved, and unlisted tools fall through to `permission_mode` and `can_use_tool` for a decision. It does not remove tools from Claude's toolset. To block specific tools, use `disallowed_tools`.

Підтверджено емпірично на CLI: з `--allowedTools "Bash(git log:*)"` агент виконав `echo GATE_9137`, і `permission_denials` лишився порожнім. Блокування досягається лише через `--tools` (склад toolset) або `--disallowedTools` (чорний список).

Додаткова пастка оточення: змінна `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB` у `~/.claude/settings.json` **примусово скидає** `permission_mode` у `default` для будь-якого підпроцесу `claude`, і попереджає про це в stderr.

### 5.1. Чому `can_use_tool` не є простою заміною

Прочитано в коді пакета, не в документації. Три обмеження, кожне здатне тихо вимкнути охоронця:

1. **Streaming-режим обов'язковий.** `claude_agent_sdk/client.py` кидає `ValueError: can_use_tool callback requires streaming mode. Please provide prompt as an AsyncIterable instead of a string.` Якщо промпт передано рядком у `query()`, callback не викликається **мовчки** - без помилки, з порожнім списком рішень. Перший probe цієї сесії саме на цьому і дав хибно негативний результат.

2. **Затінення через `allowed_tools`.** `types.py:1833-1893`, функція `_get_can_use_tool_shadowed_warning`. Запис, що дозволяє інструмент цілком (`"Bash"`, `"Bash()"`, `"Bash(*)"`), авто-схвалює його **до** охоронця. Запис зі специфікатором (`"Bash(git log:*)"`) не затіняє інструмент повністю, але дозволені ним виклики все одно проходять повз. Коментар у коді: «Allow rules from settings files can also shadow the callback but are not visible here» - тобто затінити може і `.claude/settings.json`, і SDK цього не побачить. Звідси вимога `setting_sources=[]`.

3. **`permission_mode="bypassPermissions"`** вимикає callback повністю.

SDK емітить це як `CanUseToolShadowedWarning`; під дефолтним фільтром Python попередження показується **один раз на процес**, тому в довгому запуску його легко не побачити.

4. **Взаємовиключність.** `can_use_tool` разом із `permission_prompt_tool_name` дає `ValueError` - SDK сам виставляє `"stdio"` всередині `_configure_can_use_tool`.

### 5.2. Механізм, який рекомендує сам SDK

Той самий блок коду двічі повторює: **«To gate every tool call, use a PreToolUse hook instead.»** Тобто для тотального гейтингу призначений не `can_use_tool`, а `PreToolUse` hook через `options.hooks`.

### 5.3. Підтверджений механізм пісочниці

Перевірено 2026-08-28 скриптом `tools/sync_features/probe_sandbox.py`, обидва прогони власноруч.

```python
ClaudeAgentOptions(
    tools=["Bash", "Read", "Edit"],       # зовнішня межа: інших інструментів не існує
    max_turns=N,
    model="claude-haiku-4-5",
    setting_sources=[],                    # відрізає allow-правила з settings.json
    hooks={"PreToolUse": [HookMatcher(matcher=..., hooks=[gate])]},
    stderr=<callback>,                     # інакше попередження CLI не видно
)
```

Hook повертає:

```python
{"hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "deny",          # або "allow"
    "permissionDecisionReason": "<текст>",
}}
```

Результати вимірювання:

| Тест | Виклик `Bash` | Рішення охоронця | Вивід виконання | Витік маркера |
|---|---|---|---|---|
| негативний (`echo GATE_9137`) | відбувся | DENY | порожній | немає |
| позитивний (`git log --oneline -3`) | відбувся | ALLOW | три коміти | немає |

**Методологічна пастка вимірювання.** Коли hook відхиляє команду, CLI повертає моделі рядок причини, і в ньому цитується сама заборонена команда. Наївний пошук маркера по всьому потоку подій знайде його і зафіксує «витік» саме тоді, коли захист спрацював. У пошук беруться лише `ToolResultBlock` з `is_error=False` - тобто справжній вивід виконання, не текст спроби.

**`can_use_tool` у версії 0.2.147 не викликався в жодній перевіреній конфігурації**, включно зі streaming-промптом і порожнім `allowed_tools`. Обмеження з 5.1 задокументовані в коді пакета, але не пояснюють цю поведінку повністю. `PreToolUse` hook працює - на ньому і будуємо.

**Відома діра probe, яку продукт мусить закрити:** `HookMatcher(matcher="Bash")` гейтить лише `Bash`. `Read` і `Edit` проходять без перевірки. Продукт зобов'язаний гейтити всі три виміри, інакше `Edit` перепише будь-який файл у репозиторії.

**Наслідок для специфікації:** R3b вважається виконаною лише тоді, коли існує **негативний тест**, який доводить відмову, **і** позитивний контроль, який доводить, що дозволене проходить. Конфігурація, що виглядає як пісочниця, але не блокує, вимогу не закриває. Конфігурація, що блокує все, теж її не закриває.

## 8. Обмеження середовища

- `python3` у системі - 3.14.6, і `python3 -m venv` на ній падає на `ensurepip`. Потрібен інший інтерпретатор.
- Мережа в пісочниці Bash відкрита тільки на `pypi.org` і `files.pythonhosted.org`. Виклики до `api.anthropic.com` потребують запуску поза пісочницею.
- Аутентифікація: OAuth (`claude auth status --json` дає `loggedIn: true`). `ANTHROPIC_API_KEY` локально не потрібен - SDK викликає локальний бінарник `claude` через subprocess і успадковує сесію. R3d від цього не скасовується: код усе одно читає ключ лише з env і ніколи не пише його у файл.
- `claude` CLI версії 2.1.236 у PATH.

## 9. Правила проєкту, що зв'язують реалізацію

- TDD обов'язковий (`.claude/rules/workflow.md`): тест перед кодом для всіх чистих функцій. Обгортку агента TDD не покриваємо - виклик недетермінований, мокати `query()` заради мока сенсу немає.
- `flake8` має виходити чисто, нуль знахідок. Конфіг у `setup.cfg`.
- `black .` запускається **перед** `flake8`.
- Коментарі і документація українською; ідентифікатори англійською.
- Ніколи не комітити і не пушити без явного дозволу користувача.
- Ніколи не передавати в bash, логи чи зовнішні API вміст `.env`, ключі або персональні дані.
