# django-guardrails

Детерміновані гейти якості для Django/DRF-репозиторіїв, зібрані в один Claude Code plugin.
Версія `0.1.0`.

## Purpose

Промпт "не чіпай `.env`" не є гарантією: він конкурує з рештою контексту і програє тим
частіше, чим довша сесія. Гейт - інша категорія. Він виконується поза моделлю, до виклику
інструмента, і повертає рішення кодом виходу.

Плагін закриває чотири втрати, які в Django-проєкті не відкочуються:

- **`.env` затертий.** `permissions.deny` забороняє `Read(**/.env)`, але не `Write`. Файл
  лежить у `.gitignore`, тож відновлювати його нізвідки - ані з дерева, ані з історії.
- **Секрет у трекованому файлі.** Потрапивши в коміт, ключ лишається в історії назавжди,
  навіть якщо наступний коміт його прибере.
- **Міграція видалена або відкочена.** Зниклий файл розриває граф `dependencies`, а рядок у
  таблиці `django_migrations` лишається - після цього падає кожна команда `manage.py`.
- **`group_send()` усередині `transaction.atomic()`.** Подія летить підписникам ДО коміту.
  Відкат лишає WebSocket-клієнтів зі станом, якого в базі немає. Баг проявляється тільки під
  відкат, тобто рідко і не в тестах.

Плюс skill, який відмовляється вважати зелений прогін доказом і перевіряє тести мутаціями
(навмисне псування коду під тестом: якщо тест не почервонів, він нічого не перевіряв).

## Install

Ефемерний запуск без встановлення, для розробки і перевірки:

```bash
claude --plugin-dir ./django-guardrails
```

Постійне встановлення на весь репозиторій, з комітом у `.claude/settings.json`. `install`
резолвить плагін через marketplace, тому спершу треба зареєструвати той, що лежить у самому
плагіні (`.claude-plugin/marketplace.json`):

```bash
claude plugin marketplace add ./django-guardrails
claude plugin install django-guardrails@django-guardrails-dev --scope project
```

Без `--scope project` запис піде у твій `~/.claude/` і колеги плагіна не побачать.

Залежності на машині: `bash`, `jq`, `python3` (хуки на stdlib, без пакетів), `git`.
Скрипти skill (`preflight.py`, `mutate.py`) мають shebang `uv run`, але викликаються завжди
через `python3`, тому `uv` потрібен лише якщо запускати їх напряму як `./mutate.py`.
`black` і `flake8` беруться з `.venv/` цільового проєкту, а якщо їх там немає - з `$PATH`.
Хуки читають конфігурацію на старті сесії, тому після правки `hooks/hooks.json` потрібен
рестарт; для команд і skill вистачає `/reload-plugins`.

## Commands

| Команда | Що робить |
|---|---|
| `/django-guardrails:gate` | Прогін `black` -> `flake8` -> `manage.py test` саме в цьому порядку, бо `black` переписує, а `flake8` тільки звітує. Приймає необовʼязкову ціль: `/django-guardrails:gate working_form`. Нічого не комітить. |
| `/django-guardrails:hooks-matrix` | Самоперевірка хуків: 43 синтетичні payload через stdin, звіряється вихідний код. Ловить обидва тихі стани зламаного гейта - "перестав блокувати" і "блокує все підряд". |

Коротких форм `/gate` і `/hooks-matrix` не існує: namespace-префікс у плагінних команд
обовʼязковий, і саме він робить неможливим конфлікт із чужою командою `gate`.

## Skills

| Skill | Коли вмикається |
|---|---|
| `scaffold-tests` | Коли просять написати або розширити тести, підняти покриття, або відповісти "а ці тести взагалі чогось варті". Створює файл за конвенціями репозиторію (`APITestCase`, літеральні URL, перевірка і статусу, і рядка в БД), потім доводить його чинність AST-мутаціями і оновлює реєстр покриття проєкту. |

Skill свідомо не запускається від слова "scaffold" - опис описує ситуацію, а не назву.

## Hooks

| Подія | Matcher | Скрипт | Поведінка |
|---|---|---|---|
| `PreToolUse` | `Write\|Edit\|MultiEdit\|NotebookEdit` | `protect-secrets.py` | **Блокує** (exit 2) запис у `.env`, `*.pem`, `*.key`, `credentials*`, `id_rsa` і запис секрето-подібного літерала у трекований файл. `.env.sample` і плейсхолдери дозволені. |
| `PreToolUse` | `Write\|Edit\|MultiEdit\|NotebookEdit` | `guard-layering.py` | **Блокує** появу `group_send`, `channel_layer`, `get_channel_layer` чи імпорту `channels` у будь-якому `services.py`. Коментар про `group_send` порушенням не вважається. |
| `PreToolUse` | `Bash` | `guard-migrations.sh` | **Питає дозвіл** (`permissionDecision: ask`) на `rm`/`mv`/`git checkout`/`git reset` по міграціях, на `git clean` у будь-якому вигляді і на перенаправлення виводу у файл міграції. |
| `PostToolUse` | `Bash` | `check-new-migrations.sh` | Звужується сам до `makemigrations`, далі підсвічує `RemoveField`, `DeleteModel`, `Rename*` у незакомічених міграціях: це `DROP COLUMN`/`DROP TABLE` і блокування таблиці на Postgres. |
| `PostToolUse` | `Write\|Edit\|MultiEdit` | `format-python.sh` | Прогін `black` по щойно записаному `.py`. Ніколи не блокує. |

Усі шляхи всередині `hooks.json` побудовані на `${CLAUDE_PLUGIN_ROOT}`. Виняток - `black`,
який шукається під `$CLAUDE_PROJECT_DIR`: інтерпретатор і лінтер належать цільовому
проєкту, а не плагіну.

Гейти fail-open: несподіваний payload дає exit 0. Зламаний гейт, що блокує все підряд,
знімають цілком, і репозиторій лишається взагалі без захисту - тому дешевше пропустити
сумнівний випадок, ніж зупинити роботу.

Плагінні хуки **складаються** з хуками проєкту, а не заміщають їх. Якщо той самий гейт уже
прописаний у `.claude/settings.json`, він відпрацює двічі.
